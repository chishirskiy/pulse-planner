# Пульс 3.0 — облачный планировщик

**Что есть:** задачи на день/неделю/месяц, календарь, переносы, повторы, подзадачи, привычки, фокус-таймер, статистика, экспорт JPG/TXT/ICS, импорт и экспорт `.cfg` версий 1.0, 2.0 и 3.0. **Новое:** личный аккаунт Supabase, синхронизация между ПК и телефоном, офлайн-очередь изменений и установка на главный экран (PWA).

## Подключение за 10 шагов

1. Перейди на https://supabase.com/dashboard и создай проект (**New project**). Дождись, когда проект будет запущен.
2. В Supabase зайди в **SQL Editor** → **New query**. Открой файл `supabase_setup.sql`, скопируй его целиком, вставь в редактор и нажми **Run**. Это создаст таблицу `pulse_items` и политики RLS (каждый пользователь может видеть и изменять только свои данные).
3. Открой **Project Settings / API Keys** (в некоторых интерфейсах — **Connect**) и скопируй **Project URL** (`https://...supabase.co`) и **Publishable key**, начинающийся с `sb_publishable_`. **Secret key и service_role запрещены в браузере.**
4. В папке сайта открой файл `config.js` в любом редакторе и подставь свои значения:

   ```javascript
   window.PULSE_CONFIG = {
     url: 'https://YOUR_PROJECT.supabase.co',
     publishableKey: 'sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ'
   };
   ```

   Ключ `sb_publishable_` **публичный**. Его разрешено хранить в браузерном коде при включённом RLS. Если не хочешь редактировать файл, эти данные можно ввести в окне «Облако» в самом сайте — отдельно на каждом устройстве.
5. Создай репозиторий на https://github.com/new (например, `pulse-planner`). Загрузить в **корень репозитория** нужно файлы из ZIP **вместе с папкой `icons`**: `index.html`, `styles.css`, `cloud.css`, `app.js`, `cloud.js`, `config.js`, `sw.js`, `manifest.webmanifest`, `icons/...` (SQL/README необязательны для работы сайта). **Не загружай никакие приватные пароли, secret/service_role и файлы с личными .cfg.**
6. В GitHub открой **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)** → Save. У тебя будет адрес вида `https://USERNAME.github.io/pulse-planner/`. GitHub Pages должен работать через **HTTPS**.
7. В Supabase открой **Authentication → URL Configuration**. Укажи `Site URL` = точный адрес Пульса из шага 6, а в **Redirect URLs** добавь этот же адрес (например, `https://USERNAME.github.io/pulse-planner/`). Это необходимо для письма подтверждения почты.
8. Открой сайт по своей HTTPS-ссылке. Нажми **«Локально» / облако** → «Создать аккаунт». Введи почту и пароль. Если включено подтверждение почты, открой письмо от Supabase, пройди по ссылке и затем войди.
9. На iPhone открой **тот же адрес** в Safari → **Поделиться** → **На экран «Домой»**. Открой установленный Пульс и войди **в тот же аккаунт**. После первой загрузки по интернету сайт будет открываться офлайн (задачи из локального кэша доступны на устройстве).
10. Для переноса записей из старой версии открой Пульс 1.0/2.0 и скачай **«Копия .cfg»**. Затем в Пульсе 3.0 открой **Настройки и данные → Восстановить .cfg** → **Объединить**. Если Пульс 2.0 и 3.0 открывались на одном и том же адресе, 3.0 также читает старое локальное сохранение в режиме гостя: войди в аккаунт → **«Перенести локальные задачи»**. Перед импортом рекомендуется скачать текущую `.cfg` на всякий случай.

## Как происходит синхронизация

- При изменении задачи Пульс **сразу** сохраняет всё в локальное хранилище браузера, после чего пытается отправить изменившиеся записи в Supabase.
- Без интернета изменения остаются в **очереди**, и индикатор показывает, сколько ожидает отправки.
- После возвращения интернета изменения отправятся при открытом сайте или при следующем открытии. Пока Пульс закрыт, **гарантированной фоновой отправки нет**.
- Второе устройство автоматически проверяет сервер **примерно каждые 15 секунд** (когда страница открыта) и при возвращении на вкладку. Есть кнопка **«Синхронизировать»**.
- Разные задачи синхронизируются отдельно. **При одновременном изменении одной и той же задачи** на двух устройствах сохраняется версия с более поздним временем изменения на устройстве; часы устройств должны быть настроены верно. Для критически важных данных делай `.cfg`.
- Удаление превращается в специальную запись-тумбстоун, поэтому после синхронизации задача не появляется снова на втором устройстве.
- Локальные записи до входа в аккаунт не загружаются в облако без твоего действия. Переход между разными аккаунтами отделяет локальный кэш каждого аккаунта.

## Ограничения / безопасность

- Это **готовый статический сайт**. Я не создавал Supabase-проект и GitHub-репозиторий в твоём аккаунте: эти шаги нужны один раз с твоей стороны. Без Project URL/Publishable key и SQL сайт работает только как локальный планировщик.
- **Никогда** не вставляй `sb_secret_...` или `service_role` в код или браузер. Доступ каждого аккаунта в базе защищён RLS. Код хранит пользовательскую сессию и локальный кэш в `localStorage` **без сквозного шифрования** — используй доверенные устройства и не сохраняй там секретные данные.
- Работа без интернета возможна **после первого успешного посещения опубликованного HTTPS-сайта** и после входа в аккаунт. Впервые зарегистрироваться/войти без интернета нельзя. Очищение данных сайта удаляет локальный кэш и отложенную очередь; облачные записи, которые уже были отправлены, остаются.
- На iPhone система может останавливать фоновые вкладки. Поэтому офлайн-изменения синхронизируются, когда приложение снова открывается и получает сеть.
- `.cfg` — **полная копия данных**, а JPG/TXT/ICS — только отчёты/календарь. Рекомендуется иногда сохранять `.cfg` вне браузера.
- На GitHub Pages исходники сайта доступны публично. **Ни пароли, ни данные пользователей в `config.js` не хранятся**; данные задач живут в Supabase. Публиковать личные `.cfg` нельзя.
- Реальную работу с собственным Supabase-проектом и письмами регистрации нужно проверить после подключения твоих ключей — локальные автоматические тесты использовали имитацию API.

## Состав папки

- `index.html` — интерфейс;
- `app.js`, `styles.css` — задачи, календарь, привычки, таймер, отчёты;
- `cloud.js`, `cloud.css` — вход, синхронизация, облачный интерфейс;
- `config.js` — публичный URL и publishable key (заполняешь сам);
- `supabase_setup.sql` — база данных и защита RLS;
- `manifest.webmanifest`, `sw.js`, `icons/` — PWA для ПК и телефона;
- `README.md` — эта инструкция.

**Если обновляешь версию сайта:** перед заменой файлов скачай `.cfg`; изменив только HTML/JS/CSS в репозитории, не удаляй таблицу `pulse_items` из Supabase. Изменения на старых устройствах сначала синхронизируй, потом устанавливай новую версию.
